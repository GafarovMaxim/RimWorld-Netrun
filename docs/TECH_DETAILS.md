# Технические правила Netrun: тики, сохранение, чистка данных, совместимость, достижения

**Инструкция для всех сессий и агентов, которые пишут код мода.** Прочитать перед тем, как добавлять новую систему, новый GameComponent, новый сохраняемый список или новую ссылку на пешку. Решения Maxim от 2026-10-07: правила по тикам и потолкам списков приняты; NetrunJanitor и достижения через VAE пока план (разделы 2.5 и 3), кода по ним нет.

Источники: код мода проверен по `Source/` на 2026-10-07; Vanilla Achievements Expanded (VAE) по его исходникам (github.com/Vanilla-Expanded/VanillaAchievementsExpanded, v3.102 от 2 октября 2026, папка `1.6`); игра по справочной сборке `Krafs.Rimworld.Ref` 1.6.4871. Идеи, на которые ссылаются примеры, описаны в [CONCEPT.md](CONCEPT.md), история в [ARCHIVE.md](ARCHIVE.md) (бывший CONCEPTS_9).

## Правила коротко (чек-лист перед коммитом)

1. **Никакой работы каждый тик.** `GameComponentTick` первой строкой проверяет интервал (`TicksGame % N != 0 → return`), минимум 250 тиков; лучше работать по событию (взлом, нырок, письмо, смерть). У пешек: `IsHashIntervalTick` для размазывания.
2. **Никаких переборов всей карты.** Только списки по def (`listerThings.ThingsOfDef`, `listerBuildings.AllBuildingsColonistOfDef`) или кэш, пересчитанный по событию.
3. **Никаких ситуативных мыслей «пешка о пешке».** Вместо них мысль-воспоминание.
4. **Alert кэширует ответ** минимум на 250 тиков.
5. **У каждого сохраняемого списка потолок** (или чистка по возрасту / сроку). Число в Def, не в коде.
6. **Ушедших и умерших пешек храним строкой** (имя, `GetUniqueLoadID()`), не ссылкой. Ссылка на пешку только пока она жива и на карте; после загрузки выбрасываем `null`.
7. **Не удерживаем пешек в мире** (`KeepForever`), не патчим `WorldPawnGC`, не вызываем `GC.Collect`.
8. **Хедиффы без своего тика**, где можно; длительность через `HediffComp_Disappears`.
9. **Новая система с сохраняемыми данными реализует `Cleanup`** для NetrunJanitor (когда он появится, раздел 2.5).
10. **Совместимость с другими модами только мягкая:** `MayRequire`, `LoadFolders.xml` с `IfModActive`, отдельная сборка в условной папке. Основная сборка не зависит ни от каких модов, кроме HE и Harmony.

## 1. Тики

### 1.1 Что такое тик

Тик это один шаг симуляции мира. За тик пешки делают шаг, растения растут, огонь горит. Сколько тиков в секунду:

| Скорость | Тиков в секунду (примерно) |
|---|---|
| Скорость 1 (обычная) | 60 |
| Скорость 2 (x3) | 180 |
| Скорость 3 (x6) | 360 |
| Ультра (dev) | столько, сколько потянет процессор |

Всё, что делается «каждый тик», на третьей скорости повторяется 360 раз в секунду. Если это стоит 0.1 мс, то там мы забираем 36 мс в секунду, а это уже заметная потеря скорости. Поэтому главный вопрос любой механики: **как часто она работает и сколько стоит один раз**.

### 1.2 Ритмы игры

| Ритм | Как часто | Кто так живёт |
|---|---|---|
| Normal | каждый тик | пешки (движение, бой), снаряды, огонь |
| Rare | раз в 250 тиков (~4 с на обычной скорости) | большинство построек, батареи, растения в горшках |
| Long | раз в 2000 тиков (~33 с) | растения на полях, медленная порча |
| Час | 2500 тиков | удобная единица для «раз в час» |
| Сутки | 60 000 тиков | |

В RimWorld 1.6 у пешек и хедиффов есть ещё `TickInterval(delta)`: игра сама реже тикает неважные вещи и передаёт, сколько тиков прошло (`delta`). Есть и способ размазать работу: `pawn.IsHashIntervalTick(60)` у каждой пешки срабатывает в свой тик. Тогда 20 пешек не проверяются в одном и том же кадре, и не бывает рывков.

### 1.3 Из чего складывается цена

**Цена = частота × объём работы за раз.**

- Частота: каждый тик, раз в 250, раз в час, только по событию.
- Объём: проверить одно число (почти бесплатно) или пройти по всем вещам карты (дорого: на большой колонии их десятки тысяч).

| Дёшево | Дорого |
|---|---|
| По событию: закончился взлом, нырок, пришло письмо, пешка умерла | Каждый тик |
| Раз в 250 тиков по нескольким объектам | Перебор всех вещей или построек карты: `map.listerThings.AllThings`, `map.listerBuildings.allBuildingsColonist` с фильтром |
| Список вещей по конкретному def: `listerThings.ThingsOfDef(NR_AIFragment)` (игра хранит его готовым) | Ситуативные мысли «пешка о пешке» (`ThoughtWorker` для социальных мыслей): игра считает их **попарно**. 20 колонистов = 380 пар, и это повторяется регулярно |
| Мысль-воспоминание (`Thought_Memory`): вешается один раз, дальше игра только уменьшает таймер | Хедифф со своим тиком, если он висит на всех пешках |
| Посчитать один раз и запомнить в поле | LINQ (`Where`, `OrderBy`, `ToList`) в коде, который вызывается часто: каждый вызов создаёт мусор для сборщика памяти |
| `Alert` с кэшем на 250 тиков | `Alert` без кэша: игра опрашивает предупреждения часто, и каждое тяжёлое предупреждение тормозит |

### 1.4 Как устроено сейчас у Netrun

Все компоненты мода вызываются игрой каждый тик (так устроен `GameComponentTick`), но первой строкой проверяют, пора ли работать, и сразу выходят:

```csharp
public override void GameComponentTick()
{
    if (Find.TickManager.TicksGame % TickInterval != 0)
        return;            // 249 тиков из 250 работа заканчивается здесь
    ...                    // настоящая работа раз в TickInterval
}
```

| Компонент | Интервал | Что делает |
|---|---|---|
| HeatTracker | 250 (история: раз в час) | остывание Heat, точка графика |
| NetsickManager | 250 | рост и остывание Netsick |
| ContractManager | 250 | сроки контрактов |
| AIEventManager | 250, и только если есть ожидающие события | срок ответа на письма ИИ |
| MapEvents | 250 | расписание событий карты |
| NetworkGate | 2000 | открыт ли доступ к сети, онбординг |
| FixerManager | 2500 | смена пула, молчание |
| AIManager | 2500 (час) | голод, доверие, побег, просьбы |
| Срыв «тяга к сети» | раз в 60 тиков, только у пешки в этом срыве | пешка идёт к капсуле |

Хедиффы мода (Netsick, ИИ-сокет) своего тика не имеют. Итог: **по тикам мод лёгкий**. Самое тяжёлое у мода это окно терминала, но оно рисуется только пока открыто, и игра в это время на паузе.

### 1.5 Где будут тикать идеи CONCEPTS_9 и как сделать их дешёвыми (пример применения правил)

| Идея | Когда работает | Как сделать дёшево |
|---|---|---|
| Защита узла | в момент сетевой атаки | Брандмауэры брать списком по def, не перебором карты. Силу защиты пересчитывать при постройке, сносе и переключении, хранить числом |
| Дежурство нетраннера | капсула HE и так тикает | Свой код только при входе, выходе и в момент атаки |
| Изоляция сети | по нажатию | Флаг; атаки и услуги ИИ проверяют флаг |
| Вторжение | событие с таймером | Нода Шлюза с временем окончания; проверка в уже идущем тике Gateway |
| Баланс ИИ: сетевой шум | внутри остывания Heat (раз в 250) | Число ИИ хранить в AIManager, не пересчитывать |
| Порча осколков | ванильный `CompRottable` | Ничего своего |
| Провал пробуждения | конец работы у консоли | По событию |
| Живое киберпространство | раз в сутки + по событию | Один проход по нодам Шлюза (их максимум 7) и по новостям (максимум 30) |
| Лента новостей | по событию | Новость создаётся там, где событие уже обрабатывается |
| Счётчики нырков | конец нырка | Ванильные записи пешки (раздел 3) |
| Черты-итоги | конец нырка | Проверка порога после увеличения счётчика |
| Атрофия | выход из капсулы | Хедифф с длительностью, исчезает сам (`HediffComp_Disappears`) |
| Мнение «Живёт в капсуле» | — | **Не** ситуативная социальная мысль (попарно), а воспоминание у супруга после долгого нырка. Это единственное место в CONCEPTS_9, где легко незаметно сделать дорого |
| Рассказы о нырке | ванильное взаимодействие | `InteractionDef` с весом через `InteractionWorker`, игра сама решает когда |
| Оцифровка | операция | По событию |
| Квесты ИИ | ванильный `Quest` | Шаги слушают события мода; ничего не опрашивают |
| GameCondition (шторм, изоляция) | ванильный механизм | Своего тика нет, только начало и конец |
| Alert (ИИ голодает, вторжение) | игра опрашивает | Ответ кэшировать на 250 тиков |
| Достижения через VAE | по событию (раздел 3) | VAE ловит события сам; мы ничего не опрашиваем |

**Два правила, которых достаточно для всего CONCEPTS_9 (пункты 2 и 3 чек-листа):**
1. Никаких ситуативных мыслей «пешка о пешке».
2. Никаких переборов всех вещей и построек карты; только списки по def и по событию.

## 2. Потолки списков

### 2.1 Почему список без потолка опасен

Всё, что мод пишет в `ExposeData`, попадает в файл сохранения.

1. **Размер и загрузка.** Список, в который только добавляют, растёт всю игру. На третий игровой год журнал из 5000 записей заметно увеличивает файл и время загрузки.
2. **Память и интерфейс.** Каждый показ экрана с этим списком обходит его целиком. Чем длиннее список, тем дольше рисуется экран.
3. **Ссылки на пешек.** Игра сама удаляет «ненужных» мировых пешек (WorldPawnGC: умершие давно, ушедшие гости и т.п.). Если мод хранит ссылку на такую пешку, после загрузки в логе ошибка «Could not resolve reference» и пустое место в списке. Отсюда правила:
   - ссылку на пешку хранить только пока она жива и важна;
   - ушедших и умерших хранить **строкой** (имя), а не ссылкой;
   - словари «пешка → что-то» чистить при смерти и уходе, а при загрузке выбрасывать `null`.

### 2.2 Как ставить потолок

```csharp
private const int MaxNews = 30;

public void AddNews(NewsItem item)
{
    _news.Add(item);
    if (_news.Count > MaxNews)
        _news.RemoveRange(0, _news.Count - MaxNews);   // выбрасываем самые старые
}
```

Для записей с датой можно чистить по возрасту: `_days.RemoveAll(d => d.day < today - KeepDays)`. Для словарей с таймером: удалять просроченные ключи при загрузке и раз в сутки.

### 2.5 Свой «сборщик мусора»: NetrunJanitor

Это не настоящий сборщик памяти: память C# освобождает сама среда (Mono GC), управлять ею мы не можем и не должны. Речь о **сборщике мусора в данных мода**: один компонент, который регулярно проходит по всему, что мод хранит, и убирает лишнее. Сейчас каждый менеджер чистит себя сам и по-своему, а часть не чистит совсем (`_banned`).

**Что он делает**

| Задача | Пример |
|---|---|
| Держит потолки списков | журнал Heat 200, новости 30, отчёты 10; если где-то забыли обрезать, обрежет он |
| Удаляет просроченное | запреты фиксеров с истёкшим сроком, эффекты нод, выгоревшие ноды, старые новости |
| Чинит ссылки на пешек | пешка умерла или удалена игрой → ссылка заменяется именем-строкой или запись удаляется; `null` после загрузки выбрасываются |
| Чинит ссылки на вещи | захваченные турели, серверы ИИ: уничтоженные убираются |
| Проверяет def после обновления мода | если в сохранении остался def, которого больше нет (переименовали демона, убрали чип), запись удаляется вместо ошибки в логе |
| Убирает дубли | два ИИ с одним id, повторные записи в «найденных» |
| Чистит кэши интерфейса | при закрытии терминала: кэши текста, высот, пересобранные текстуры (часть уже есть в `NetrunUI`, его вызов переезжает сюда) |

**Как устроен**

```csharp
// Любой менеджер мода, у которого есть что чистить
public interface INetrunCleanable
{
    // Возвращает, сколько записей удалено или исправлено (для отчёта)
    int Cleanup(CleanupReason reason);
}

public enum CleanupReason { Loaded, Daily, Manual }
```

- `NetrunJanitor` (GameComponent) знает список всех `INetrunCleanable`: Heat, Gateway, Fixers, Contracts, AI, MapEvents, Braindance, новости, квесты ИИ и т.д.
- **Когда работает:**
  1. после загрузки сохранения (`FinalizeInit`): главный проход, чинит всё, что сломалось за время обновлений мода;
  2. раз в игровые сутки, в свой тик со сдвигом (не в 0:00, где тикает много всего);
  3. вручную: dev-действие «Netrun: cleanup report».
- **Потолки в одном месте:** Def `NR_Limits` (журнал, новости, отчёты, история контрактов и т.д.). Число меняется в XML, код не трогаем.
- **Отчёт:** в dev-режиме пишет в лог одну строку: «Netrun cleanup (Loaded): Heat log −0, banned fixers −3, dead pawn refs −1, unknown defs −2». В обычной игре молчит. Тот же отчёт удобно присылать после теста.

**Сколько стоит.** Проход по нескольким сотням записей раз в сутки: доли миллисекунды. Тиков не добавляет: проверка «пора ли» встраивается в уже существующий интервал.

**Что даёт**
- Старые сохранения не копят мусор, сколько бы ни шла игра.
- Обновления мода меньше ломают сохранения: удалённые и переименованные def-ы чистятся, а не сыплют ошибками.
- Новые системы CONCEPTS_9 (новости, корпорации, квесты, Наследник) получают чистку «бесплатно»: достаточно реализовать `Cleanup`.
- Одно место, где видно, что мод хранит. Это же основа для dev-отчёта о памяти из PERF_AUDIT_3.

### 2.6 Совместимость с модами-чистильщиками

Проверено 2026-10-07: описания модов (исследователь, Steam и каталоги) и справочная сборка игры 1.6 (`Krafs.Rimworld.Ref` 1.6.4871).

| Мод | Что делает | Пересечение с Netrun |
|---|---|---|
| **Better GC: Mothballed and World Pawns** | Настраивает, когда игра удаляет мировых пешек и каких «замораживает» (mothballing). Снят из мастерской; по отзывам, удалял и нужных пешек | Может удалить пешку, на которую ссылается Netrun |
| **No Reasons To Avoid Mothballing** | Только XML: разрешает «заморозку» мировых пешек с недоеданием (`allowMothballIfLowPriorityWorldPawn`). В 1.5+ почти всё уже в ванили | Нет. Подсказка: наши хедиффы тоже не должны мешать заморозке (см. ниже) |
| **World Pawn Cleaner** | Dev-действия: удалить «неважных» мировых пешек (по желанию и родню колонистов). API для других модов нет | Может удалить пешку, на которую ссылается Netrun |
| **Ванильный WorldPawnGC** | Сам периодически удаляет ненужных мировых пешек. «Нужность» считает по своим правилам (колонисты, родня, квесты, сюжеты, лидеры фракций и т.д.), ссылки из модов не учитывает | То же, что у чистильщиков, только мягче |

**Почему NetrunJanitor с ними не конфликтует.** Он работает только с данными Netrun и по трём правилам:
1. **Никогда не удаляет пешек** и не вызывает `Discard`. Пешками управляет игра и эти моды.
2. **Не патчит `WorldPawnGC`** и не трогает «заморозку».
3. **Не вызывает `GC.Collect`** и не управляет памятью Unity/Mono.

Наоборот, он делает Netrun **устойчивым** к ним: если чистильщик удалил пешку, на которую мы ссылались, Janitor при следующем проходе заменяет ссылку именем или аккуратно закрывает запись, вместо ошибки «Could not resolve reference».

**Где Netrun сейчас держит ссылки на пешек (5 мест)**

| Ссылка | Кто это | Риск | Что сделать |
|---|---|---|---|
| `NetAI.Host` | колонист с ИИ в сокете | Если носителя похитили или он ушёл, он становится мировой пешкой; агрессивный чистильщик может его удалить | При `null` ИИ «теряет связь»: письмо и осколок/уход, как при смерти носителя |
| `MapEvents._courier` | гость-курьер | Ушёл с карты → мировая пешка | Уже есть проверка на `null` |
| `PendingAIEvent.target` | цель события ИИ (колонист, пленник) | Окно 1–2 суток | Проверка на `null` при срабатывании |
| `DiveSession.Runner` | нетраннер в капсуле | Лежит на карте, игра его не удалит | Нет |
| `BraindanceRecorder._lastRecord` | колонисты | Уже чистится при загрузке | Нет |

Автор записи брейнданса уже хранится строкой: это правильный образец.

**Если пешку правда нужно помнить долго** (например, достижение «Эхо встретило своего убийцу»):
- лучше всего хранить **строковый id** (`pawn.GetUniqueLoadID()`) и имя, а сравнивать, когда пешка снова появится (рейд, гость). Никакого удержания пешки в мире, чистильщикам нечего ломать;
- ванильный способ удержать пешку есть (`Find.WorldPawns.PassToWorld(pawn, PawnDiscardDecideMode.KeepForever)`), но им не пользуемся: он раздувает мир пешек, а чистильщики его могут не уважать.

**Заморозка (mothballing).** Замороженные мировые пешки не тикают. Хедиффы Netrun своего тика не имеют, так что заморозка их не ломает. Чтобы они и не мешали заморозить пешку (например, похищенного нетраннера с Netsick), проверить по коду игры условие `ShouldMothball` и при необходимости поставить нашим хедиффам `allowMothballIfLowPriorityWorldPawn = true`, как делает мод из таблицы.

### 2.7 Миграция сейва: как добавить шаг

- Задача, меняющая формат сейва, добавляет **одну строку** в `NetrunMigration.Steps`: `(N, "что делает", MigrateVN)`, где N = последняя версия + 1; `CurrentVersion` берётся из последнего шага сам. В комментарий над `CurrentVersion` дописать «N = задача, что меняет».
- Шаг идемпотентный: повторный прогон (dev «Migration: rerun from version N», «Migration: simulate old save») ничего не ломает и не дублирует.
- Шаг бросает исключение при сбое: версия не поднимается, шаг повторится при следующей загрузке, шаги после него ждут.
- Удалённый def: добавить defName в `NetrunJanitor.KnownRemovedDefs`; `Cleanup`, выбрасывающий запись с пропавшим def, зовёт `NetrunJanitor.MissingDef` (предупреждение только для неизвестных).

## 3. Достижения через Vanilla Achievements Expanded (план)

### 3.1 Что такое VAE (по исходникам)

- packageId `vanillaexpanded.achievements`, сам требует Harmony и VFE Core. Поддерживает 1.4, 1.5, 1.6, есть папки под все DLC, включая Odyssey.
- Своя кнопка в нижнем меню, окно с вкладками, уведомление при получении, очки за достижения и **магазин наград за очки** (например, призвать караван или рейд).
- Прогресс хранится в сохранении игры.
- Достижение описывается XML-ом:

```xml
<AchievementsExpanded.AchievementDef>
  <defName>NR_Ach_FirstDive</defName>
  <label>Jacked in</label>
  <description>Complete your first dive.</description>
  <tab>NR_AchTab_Netrun</tab>
  <tracker Class="AchievementsExpanded.RecordEventTracker">
    <def>NR_Record_Dives</def>
    <count>1</count>
  </tracker>
  <texPath>UI/Achievements/NR_FirstDive</texPath>
  <points>5</points>
</AchievementsExpanded.AchievementDef>
```

Поля `AchievementDef`: `defName`, `label`, `description`, `texPath`, `bgtexPath` (свой фон), `order`, `points`, `tracker`, `tab`. **Поля «секретное» нет**: скрытых достижений VAE не умеет (см. 3.6).

Своя вкладка «Netrun» в окне достижений:

```xml
<AchievementsExpanded.AchievementTabDef>
  <defName>NR_AchTab_Netrun</defName>
  <label>Netrun</label>
  <order>10</order>
</AchievementsExpanded.AchievementTabDef>
```

### 3.2 Как работает трекер

У каждого трекера есть `MethodHook`: метод игры, на который VAE через Harmony вешает свою проверку. Например:

| Трекер | За какой метод цепляется | Поля |
|---|---|---|
| `RecordEventTracker` | `Pawn_RecordsTracker.Increment` (запись пешки +1) | `def` (RecordDef), `count`, `total` (сумма по колонистам) |
| `RecordTimeTracker` | ванильный пересчёт записей-времени | `def`, `count`, `total` |
| `HediffTracker` | `Pawn_HealthTracker.AddHediff` | `def`, `count`, `countAllMapPawns` |
| `ThoughtTracker` | получение мысли-воспоминания | `def`, `stageIndex`, `countAllMapPawns` |
| `IncidentTracker` | `IncidentWorker.TryExecute` | `def` (IncidentDef), `count` |
| `ResearchTracker` | завершение исследования | `def` |
| `QuestTracker` | `Quest.End` | `def` (QuestScriptDef), `outcome`, `count` |
| `BuildingTracker` | появление постройки | `def`, `madeFrom`, `count` |
| `ItemCraftTracker` | изготовление вещи по счёту | `def`, `count` |
| `MentalBreakTracker` | срыв от настроения | `def` (MentalBreakDef), `count` |

Всего у VAE 55 трекеров. Важное следствие для нагрузки: **VAE ничего не опрашивает**, он ловит события в момент, когда они происходят. Мы со своей стороны тоже ничего не опрашиваем.

Нюанс: `MentalBreakTracker` ловит только срывы от настроения. Наш срыв «тяга к сети» запускается стадией хедиффа Netsick, поэтому этот трекер его не увидит. Для него нужен путь из 3.4.

### 3.3 Путь А: только XML, через ванильные записи и события

Наш основной мод заводит ванильные `RecordDef` (вкладка «Записи» в карточке пешки):

| Запись | Когда +1 |
|---|---|
| `NR_Record_Dives` | конец любого нырка |
| `NR_Record_CleanExits` | чистый выход |
| `NR_Record_BlackICEPassed` | пройден элемент Black ICE |
| `NR_Record_CorpCores` | взято корп-ядро |
| `NR_Record_Comas` | кома после нырка |
| `NR_Record_AIsAwakened` | пешка пробудила ИИ |
| `NR_Record_IntrusionsRepelled` | отбито вторжение (раздел 1 CONCEPTS_9) |
| `NR_Record_TimeInRedZone` (тип Time) | время, пока Heat колонии 95+ |

Код основного мода только вызывает ванильный `pawn.records.Increment(NR_Record_Dives)`. От VAE он не зависит, и игрок видит эти числа во вкладке «Записи» даже без VAE. Это и есть ванильная интеграция, а заодно данные для черт-итогов (раздел 5 CONCEPTS_9).

Кроме записей, VAE ловит без кода: наши хедиффы (Netsick, ИИ-сокет, ожоги ICE), мысли (в том числе мысли-маркеры, см. ниже), инциденты (сетевые атаки, курьер, охота корпов), исследования (новая вкладка Netrun), квесты ИИ (если они на ванильных `QuestScriptDef`), постройки (брандмауэр, ИИ-сервер).

**Мысль-маркер.** Для событий вида «10 чистых выходов подряд» или «из Красной зоны в Тень за сутки» колонисту даётся короткая положительная мысль («На волне», «Выскользнул»). Она полезна сама по себе (настроение, это видно в игре), а VAE ловит её `ThoughtTracker`-ом. Так «серии» и «особые случаи» тоже обходятся без своего кода для VAE.

### 3.4 Путь Б: колониальные счётчики через один свой трекер

Часть достижений считает не пешка, а колония: «25 контрактов», «все 13 личностей ИИ», «8 уникальных записей», «3 закреплённых фиксера». Записи пешки тут плохо подходят: `total` суммирует только живых колонистов, и если пешка умерла, счёт падает.

Решение без зависимости основного мода от VAE:

1. В основном моде пустой статический метод-сигнал:
   ```csharp
   public static class NetrunSignals
   {
       // Вызывается при событиях, интересных достижениям. Сам ничего не делает.
       public static void Counter(string key, int value) { }
   }
   ```
   Вызовы: `NetrunSignals.Counter("ContractsDone", manager.TotalDone)`.
2. Отдельная маленькая сборка `NetrunVAE.dll` с одним классом `NetrunCounterTracker : TrackerBase`. Её `MethodHook` указывает на `NetrunSignals.Counter`. Поля в XML: `key`, `count`.
3. Эта сборка лежит в условной папке и грузится только при включённом VAE. Без VAE её как будто нет.

```xml
<!-- LoadFolders.xml основного мода -->
<loadFolders>
  <v1.6>
    <li>/</li>
    <li IfModActive="vanillaexpanded.achievements">Mods/VAE</li>
  </v1.6>
</loadFolders>
```

```
Mods/VAE/
  Assemblies/NetrunVAE.dll      ← только трекер, ~50 строк
  Defs/Achievements_Netrun.xml  ← вкладка и все достижения
  Languages/Russian (Русский)/DefInjected/AchievementsExpanded.AchievementDef/...
  Textures/UI/Achievements/...  ← иконки 64x64
```

Для сборки `NetrunVAE.dll` CI нужен `AchievementsExpanded.dll`. Его можно брать из GitHub-репозитория VAE так же, как сейчас берётся DLL Hacking Expansion. Основная сборка `HackingExpansionNetrun.dll` от VAE не зависит вообще.

### 3.7 Что это даёт и чего стоит

- Игрок с VAE получает вкладку «Netrun» с 24 достижениями, уведомлениями и очками, которые тратятся в магазине VAE.
- Игрок без VAE ничего не теряет и ничего лишнего не грузит. Записи пешки и мысли-маркеры работают и без VAE.
- Нагрузка: VAE и так патчит `Increment`, `AddHediff` и прочие методы для своих достижений; мы добавляем только свои def-ы и один пустой метод-сигнал.
- Работа: записи и мысли в основном моде (малый объём), XML достижений и переводы, 24 иконки 64x64, маленькая сборка с трекером и шаг в CI.

### 4.2 Правила интерфейса (IMGUI вызывает OnGUI 2–4 раза за кадр: Layout, Repaint, события мыши)
1. Декоративное (корпус деки, слой карты, график Heat, мини-карта, оверлей Guide, глитчи) рисовать только на `EventType.Repaint`; клики читать отдельно.
2. Выборки и подписи, зависящие от состояния игры, в `NetrunUI.Cached` (типизированный, ключи `static readonly`, без склейки строк и бокса; при переполнении LRU, а не `Clear()`). Строки: `NetrunUI.T(key)`; ширины и высоты: `NetrunUI.Width(...)`; подсказки `NetrunUI.Tip(rect, Func<string>)` (собирать только под мышью).
3. Не использовать LINQ (`ToList`, `Where`, `OrderBy`) и `new List/Dictionary` в горячих местах; не создавать Color и `System.Random` на кадр.
4. Длинные списки: рисовать только видимые строки; раскладку текста со ссылками (`HyperText`) кэшировать по (сегменты, ширина, шрифт, TextScale), рисовать прогонами, а не словами.
5. Текстуры: ничего не генерировать на кадр; пересобранные текстуры (`HeatRing` 128 px, перекраска `NetrunTint`) кэшировать по паре (текстура, цвет), старую уничтожать `Object.Destroy`, буферы пикселей переиспользовать; перекраска не в Layout.
6. Карта: статичный слой (сетка, связи, кольца, подписи, территории) в кэше, пересборка при смене карты, зума (шаг 0.1), размера окна, линзы; динамика (раннеры, пульсы, пинг, hover) без аллокаций; маршруты и список «Ближайшие 3 дня» пересчитывать при смене выбора или раз в игровой час; подписи районов раз в 2 с; поиск и список наблюдения собирать при смене данных. Лимит одновременных анимированных пакетов ≤ 6, анимации выключаются настройкой.
7. Менеджеры: `X.Get()` через статическое поле `Instance` (сбрасывать при новой игре), а не `Game.GetComponent<T>()` в кадре.
8. Поиск вещей: только по def (`listerThings.ThingsOfDef`, реестр капсул HE `MapComponent_CyberpodManager.Pods`, список `CommsConsole`), для UI `ColonyGoods.CountCached`.
9. Смена `fontSize` общих стилей при «Размер текста» не 100% перестраивает раскладку: держать свои копии `GUIStyle`, если замер покажет разницу.
10. Ограничения сохранения: журнал Heat 200 записей, история Heat 168, отчёты нырков 10, история контрактов 5, журнал нырка 8 строк, ранг 100 строк, ноды Шлюза по карте; чистит `NetrunJanitor`. Harmony-патчи на горячие методы (`IncidentWorker.CanFireNow`, `MemoryThoughtHandler.TryGainMemory`, `Pawn_MechanitorTracker.TotalBandwidth`, поиск наркотиков и еды) делать с ранним выходом по def и словарём по defName.
