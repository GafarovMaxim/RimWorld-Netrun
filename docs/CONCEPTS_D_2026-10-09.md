## D1. Интерактивная легенда карты

**Рекомендация.** Легенда — свёртываемая плашка в левом нижнем углу карты (в Guide раскрыта по умолчанию). Пункты: 6 линз, типы нод (Market, Vault, Lab, Relay и т.д.), EXIT, корпорации (цветные точки), цвета связей (известная / скрытая / закрытая). Клик по пункту подсвечивает все такие узлы (остальные приглушаются до 35%), повторный клик снимает. Только один пункт активен.
- Данные: подсветка — один `HashSet<int>` id узлов, считается при клике, не за кадр. Рисуется в слое живого поверх карты (без пересборки статичного слоя).
- Отключение: настройка «Легенда на карте».
- Стоимость: ≤ 0,2 ms (14 подписей, кэш строк по языку).

## D2. Защищённые корпоративные узлы

**Вариант A (рекомендуется): «Крепость закрыта, пока не сломана охрана».** 2–3 корпоративных узла на карте помечены замком. Ныряние внутрь запрещено, пока в соседнем узле корпорации не взломан «Шлюз охраны» (одна нода-ветка типа Gateway, которую можно сломать обычным ныряльщиком). После взлома замок снимается на 3 игровых дня, потом охрана перезагружается. Плюсы: нет тупика (всегда есть путь), награда крупнее ожидаемой для обычного узла, использует существующие ветки. Минусы: добавляет тип ветки (текст + XML + небольшая логика).

**Вариант B: «Ключ из контракта».** Контракт фиксера даёт ключ-предмет, без которого узел закрыт. Плюсы: связывает карту и Board. Минусы: ломается, если контрактов нет (риск тупика), требует предмета в сохранении, сложнее тестировать.

**Баланс (в стиле BALANCE.md).** Награда крепости ×1,8 к обычному узлу того же размера; Heat за первую попытку +0, за неудачу +6 (как у босс-узла). Доля защищённых узлов: не более 2–3 на карту, не на корпорации, с которыми Maxim ещё не видел контактов (раннее раскрытие).
- Отключение: «Защищённые узлы» (по умолчанию вкл.).

## D3. Проверка «в нужном узле» для контракта «Наблюдение» (C4)

**Формула.** Контракт получает целевой узел (случайный из известных открытых, не EXIT). Каждый игровой час засчитывается, если хотя бы один раннер находится в этом узле. Несколько капсул суммируются: узел раннера считается по каждой капсуле, за час засчитывается `min(N_раннеров_в_узле, 2)` часов (потолок 2, чтобы не ускорять кратно). `Param` остаётся накопителем тиков; в `NotifyPodTicks` добавить аргумент «узел раннера» и сравнивать с целью. Если раннер ушёл из узла — накопленные тики не сбрасываются, просто не растут. Срок контракта не меняется.

Тексты контракта (облако, для вставки):
- EN: «Keep a runner parked at **{0}** for {1} hours. The client wants eyes on that node, not just a warm seat in a pod.»
- RU: «Держите раннера в узле **{0}** {1} ч. Клиенту нужны глаза именно на этом узле, а не просто тёплое кресло в капсуле.»
- Подсказка на карте: цель контракта помечена значком ◷ и подписью «Наблюдение».
- Цена в UI: на панели контракта «в узле: {2}/{1} ч».

## D4. Блок в Core вместо фавора группы (C5)

**Рекомендация: «Сегодня на карте».** До 3 главных событий на ближайшие 24 игровых часа (таймеры ◷ из `Timeline()`, активные вторжения, закрывающиеся контракты), по строке: иконка узла, одно слово-тип, срок. Клик по строке открывает Шлюз с выбранным узлом. Без событий — «На карте тихо». Использует уже кэшируемый таймлайн (раз в игровой час), поэтому дополнительной работы нет.
- Отключение не нужно (это просто замена пустого блока).

## D5. Кулдаун и штраф за изоляцию сети

**Рекомендация: «Охлаждение портов».** После снятия изоляции повторная изоляция недоступна 6 игровых часов (в тултипе таймер). Если изоляция продлилась меньше 2 игровых часов, при снятии: +4 Heat (источник «Other», запись в журнале) и Netsick раннерам в капсулах +5 за сброс связи. Изоляция дольше 12 часов подряд — ИИ уже штрафует через `isolatedTrustPerDay`, дополнительного не нужно.
- Реализация: два поля в `NodeDefense` (`_isolationOnTick`, `_isolationOffTick`, оба в сохранении, `Scribe_Values`), проверка в `CanToggleIsolation`. Данных мало, лимиты не нужны.
- Отключение: «Охлаждение изоляции» (по умолчанию вкл.).

## D6. Позиция соперника при хаке ноды

**Рекомендация: полоса гонки.** В нырке в ноде с соперником над журналом показывается строка: «Соперник: {0} ходов до захвата» с полосой, красной в последние 3 хода (`Settings.rivalTurns - Turn`, данные уже есть). Не показывать «где он» (расположения у соперника нет), только время. Плюс предупреждение в журнале на 3 ходах до конца (одна строка, уже есть `NR_DiveLogRival` каждый ход — заменить на вызов раз в ход, но полосу рисовать из `Turn`).
- Стоимость: нулевая, один `Widgets.FillableBar` на Repaint.
- Тексты: EN «Rival: {0} turns left», RU «Соперник: ходов до захвата — {0}».

## D7. Мехи-носильщики в меню исполнителя (решение Maxim 2026-10-09)

**Решение:** мехи не кормят ИИ автоматически и сами запросы не выполняют. В меню «кто принесёт предмет ИИ» (выбор исполнителя запроса) рядом с колонистами показываются механоиды-носильщики. Выбор делает игрок; исполнение идёт обычным поручением «Доставить» для выбранного исполнителя. Фильтр: механоид, способный носить (в 1.6 Biotech — по `RaceProperties.mechEnabledWorkTypes`/работа «Hauling»; Плотве проверить точное условие). Без Biotech пункт скрыт. Новых тиков и настроек не нужно (опционально флажок «Мехи в списке исполнителей», по умолчанию вкл.).
