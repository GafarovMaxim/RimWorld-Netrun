Правила: `docs/TECH_DETAILS.md` обязательны (без работы по тику, без аллокаций в OnGUI, закрытые списки в сохранении, кэш по изменению, а не по кадру). Рутинное чтение и сравнение файлов отдавать агенту на Haiku.

Исполнители: **Плотва** (C#, UI, баги в коде, замеры в игре), **облако** (тексты, XML, документы, аудит кода, концепты). Концепты не реализуются до слова Maxim.

Порядок: сначала A (производительность), затем B (баги), затем C (изменения), D (концепты: только предложения).

## A. Производительность (первым)

Симптомы от Maxim: TPS проседает до 500–600 при скорости 4 (Smart Speed, 900 TPS); в окне терминала до 17 ms в активном Guide.

- [x] **A1. Замер терминала (Плотва).** Замерить время `Dialog_NetTerminal` по экранам (навигация, Gateway, Club, Board, Archive, Server, Studio, меню) с Guide включённым и выключенным. Цель: ≤ 2 ms на кадр в каждом экране, ≤ 5 ms с Guide. Вывод в строке `dev: draw` уже есть, добавить максимум и среднее за 5 с. **Сделано Плотвой:** в режиме разработчика строка «dev: draw X ms · 5s avg Y max Z» (и пометка guide), каждые 5 с то же пишется в Player.log с именем экрана: `[Netrun] Gateway: dev: draw …`.
- [x] **A2. Guide (Плотва).** Области Guide вычисляются, пока Guide открыт, на каждом кадре (по коду и по симптому 17 ms). Кэшировать рамки и тексты областей по размеру окна и языку; пересчитывать только при смене экрана, размера или текста. **Сделано Плотвой:** области Guide собираются только при включённом Guide (раньше на каждом кадре), замена области по словарю вместо RemoveAll с лямбдой, список описаний экрана кэшируется, готовый список областей строится раз за кадр, наведение без LINQ.
- [x] **A3. Аудит оптимизации (координатор, не облако).** Maxim попросил провести аудит координатора. **Готово:** отчёт в [docs/PERF_AUDIT_4.md](PERF_AUDIT_4.md) (коммит 470441b). Главная гипотеза: открытый терминал не на паузе, и его отрисовка (до 17 ms на кадр) режет TPS; проверка A/B в п. 3 таблицы отчёта. Пять несобранных правок из отчёта (раздел «Правки, уже внесённые») Плотве собрать и проверить.

Проверить, что пинг не сканирует все узлы каждый раз. **Сделано Плотвой:** «Ближайшие 3 дня» и метки ◷ пересобираются раз в игровой час, между пересборками время отсчитывается вычитанием; автопауза идёт в шаге раннеров (раз в 250 тиков); пинг собирает узлы в радиусе одним обходом, а не поиском на каждую скрытую ноду.
- [x] **A5. Лимиты сохранения.** Аудит координатора, см. [docs/PERF_AUDIT_4.md](PERF_AUDIT_4.md) (пункт A3). Плотва не трогает лимиты до отдельного решения.

## C. Изменения (Плотва, с понятным описанием)

- [x] **C1. Нечёткий поиск.** Ответ на вопрос Maxim: дёшево. Список узлов, нод и корпораций короткий (порядка 200 строк), сейчас поиск по подстроке пересобирается только при изменении текста, а не по кадру (`GatewayMapV4.FindHits`). Нужно: нормализовать строки (нижний регистр, убрать пробелы, дефисы и знаки), сравнивать и с запросом без разделителей, чтобы «83», «Market 83» и «market-83» находили `Market-83`. Стоимость: один проход по ~200 строкам при вводе символа, меньше 0,1 ms. Важно: по коду «83» уже должно находить `Market-83` (подстрока), поэтому Плотве сначала воспроизвести: проверить, что именно не находилось. **Сделано Плотвой:** поиск без учёта регистра, пробелов, дефисов и знаков.

- **D9. Карта визуально ближе к концепту v4.** Облако сравнивает скриншот Maxim с макетом 34a/34b и составляет список расхождений (отдельно, после скриншотов Maxim).
