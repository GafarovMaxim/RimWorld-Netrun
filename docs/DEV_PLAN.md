# План разработки v3: задачи по сессиям

Создан 2026-10-28 по `docs/BALANCE_PLAN.md` v3.1. Одна задача = одна сессия Claude. Задачи упорядочены по зависимостям и собраны в этапы; каждый этап собирается, проверяется Maxim в игре и может уйти релизом.

## Как пользоваться
1. Берёшь следующую задачу, у которой готовы зависимости.
2. Открываешь новую сессию с нужной моделью и вставляешь бриф из блока задачи целиком.
3. Сессия делает задачу, проходит «Готово, когда» и коммитит одним логическим шагом.
4. В конце этапа Maxim проходит тест этапа (шаги в задачах и общий тест этапа) и присылает лог.

**Модель:** S и M → Sonnet; L → Opus; рискованное ядро (сохранения, нырок, генератор графа, Harmony на ванильные системы) и задачи, где больше дизайна, чем кода, → Opus даже при M. Рутинная работа с данными внутри сессии (сравнение строк, поиск, переименования) уходит агенту Haiku (правило CLAUDE.md).
**Размер:** S ≈ до 2 ч работы сессии, M ≈ одна полная сессия, L ≈ сессия на пределе (если не влезает, делится на «а/б» в самой сессии с отдельными коммитами).

## Общие «Готово, когда» (DoD) для каждой задачи
1. `dotnet build Source/Netrun.csproj -c Release`: 0 ошибок, 0 предупреждений.
2. `python tools/check_keys.py` без пропусков; `python tools/ru_lint.py` без ошибок (EN и RU строки добавлены вместе).
3. Правила `docs/TECH_DETAILS.md` (чек-лист «Правила коротко»): нет работы каждый тик, потолки списков в Def, `Cleanup` для `NetrunJanitor`, пешки строкой.
4. Сохранение: новые поля с умолчанием, null-проверки после загрузки; если формат сейва изменился, шаг в `NetrunMigration` (версия = этап + 1, см. BALANCE_PLAN 20).
5. Киберпедия, подсказки, dev-действия по таблице BALANCE_PLAN раздел 17 для этой задачи; всплывающий термин из `docs/MECHANICS.md` 22, если он относится к задаче (после T3.8).
6. `docs/MECHANICS.md`: блок механики переведён из [план] в [есть], числа из Defs.
7. `CHANGELOG.md` [Unreleased]: одна строка; `docs/STATUS.md` и `docs/TASKS.md` обновлены.
8. В ответе Maxim: что изменено, где файлы, **шаги теста в игре** (dev-действия, что смотреть, что должно быть в логе).
9. Коммит и `git push` одним логическим шагом.
